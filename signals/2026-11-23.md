# Self-Custody & Sovereignty Signal Report — Week of Nov 17 – 23, 2026

## Top 3 Signals

### 1. Independent Keylabs Review Confirms COLDCARD's July 2026 RNG Fix in Shipped Firmware; the Fix Does Not Repair Seeds Already Generated on Affected Firmware
🟠 Emerging · formal · technical · hardware, threat, key-mgmt · [Vendor security report]

**Summary:** COLDCARD's security status page records on November 21, 2026 that Coinkite "Added the independent Keylabs source-and-binary review of the July 2026 RNG remediation." The defect was that "rng_get() resolved to MicroPython's Yasmarang software generator instead of the STM32 hardware RNG"; Keylabs found the remediation in Mk5 5.6.2/5.6.3 and Q 1.5.2Q/1.5.3Q sound and confirmed it in the shipped binaries. Coinkite states that Edge firmware was outside the review, that it was not a complete audit, and that seeds already generated on affected firmware are not repaired: the blog post says those users must create a new seed using corrected firmware and move the funds, and the status page exempts seeds that included enough independent dice rolls.
**Filter:** A firmware update cannot repair a seed generated with weak entropy, so the remedy for affected holders is to generate a new seed and move funds themselves.
**Source:** [Vendor security report] https://coldcard.com/security/status · 2026-11-21
**Also:** https://blog.coinkite.com/keylabs-coldcard-seed-generation-review/ · https://blog.coinkite.com/reports/coldcard-seed-generation-review-keylabs-2026-10-15.pdf

### 2. Safe's New Queue Service Drops a Removed Owner's Pending Signatures and Delegations and Rejects Unsigned Proposals
🔴 Strong · in-force · technical · key-mgmt · [Protocol blog]

**Summary:** Safe says its new queue service is live in production and that "When an owner is removed from a Safe, their pending signatures and delegations are removed too" and "The queue never shows an approval from someone who is no longer a signer." "The service rejects unsigned proposals": each proposal must carry a valid signature from an owner, a delegate, or the owner of an owner Safe, and the proposer is identified from it. The service also rejects new signatures on executed transactions, returns a transaction to pending if a reorg reverses its execution, and removes the old Transaction Service endpoints on 19 January 2027.
**Filter:** A signer removed from a multisig no longer leaves approvals behind that count toward pending transactions, so the current owner set alone decides what can be executed.
**Source:** [Protocol blog] https://safe.global/blog/new-queue-service-multichain-by-default · 2026-11-19

### 3. Liana v16.0 Writes Encrypted Descriptor Backups in BIP138 Format and Makes Taproot the Default for New Wallets (Optech #432)
🔴 Strong · in-force · technical · recovery, key-mgmt · [Protocol blog]

**Summary:** Optech #432 reports that Liana v16.0 "writes its encrypted descriptor backups in the BIP138 format" and "makes taproot the default for new wallets". The release notes say the backup is now a BIP138 v1 `.bip138` file instead of a `.bed` file, that Liana v15 and below cannot read it, that older `.bed` and base64 backups still decrypt, and that a warning is added when a recovery transaction sends to an address of the same wallet.
**Filter:** Restoring a Liana wallet needs the descriptor as well as the keys, so the backup format decides which software versions can bring the wallet back.
**Source:** [Protocol blog] https://bitcoinops.org/en/newsletters/2026/11/20/ · 2026-11-20
**Also:** https://github.com/wizardsardine/liana/releases/tag/v16.0

## UX & Interaction Signals

### Safe Pro Makes the Workspace the Account, but "No Workspace Role Grants Signing or Execution Authority", with TOTP Step-Up for Admin Changes
🔴 Strong · in-force · technical · ux, identity · [Protocol blog] · `access-signing-separation`

**What changed:** Safe says "Safe Pro makes the Workspace the account," with Admin and Member roles, and "No Workspace role grants signing or execution authority over a Safe"; signing stays with each Safe's owners and onchain threshold. Changes to shared data again require a TOTP for email and Google sign-ins, and "Wallet sign-in doesn't have 2FA yet, and that's a gap we're working on." Safe{Wallet} stays free with no login, and if a Pro subscription ends the Workspace locks while signing keeps working.
**Experience filter:** Users of the team workspace must understand that logging in gives them visibility and the ability to prepare transactions, while approval still comes from their own keys and the Safe's threshold.
**Design read (analysis):** The product states in its own words that the account a user logs into is not where custody sits, which addresses a confusion a web2-style login on top of key-based authority could otherwise create.
**Source:** [Protocol blog] https://safe.global/blog/authentication-is-not-authorization-how-safe-pro-separates-access-from-signing · 2026-11-18
